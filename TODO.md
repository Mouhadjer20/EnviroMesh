# PART 1 — PROJECT CONTEXT

## 1.1 Project identity

Project name: **EnviroMesh**

Project description:

EnviroMesh is a smart environmental monitoring network that collects environmental sensor measurements from distributed ESP32 nodes using LoRa and Wi-Fi communication.

The system monitors environmental conditions in different zones and warehouses. It collects sensor data, processes and stores telemetry, provides a centralized dashboard, and supports alerts and actuator commands.

The system must be reliable during network interruptions, secure against unauthorized access, modular, maintainable, and suitable for deployment on Raspberry Pi hardware.

## 1.2 Existing technology stack

Inspect the repository and preserve the existing technologies and application structure wherever possible.

The intended stack is:

- Embedded hardware: ESP32.
- LoRa communication: SX1278 RA-02, 433 MHz.
- Gateway hardware: Raspberry Pi 4 Model B.
- Core hardware: Raspberry Pi (target Raspberry Pi 4 Model B).
- MQTT brokers: EMQX 5.x on both Raspberry Pis.
- Gateway programming: Python 3.
- Gateway offline storage: SQLite.
- Backend: Python FastAPI.
- Central database: PostgreSQL with TimescaleDB extension.
- Frontend: React + Vite.
- Charts: Recharts, if already used by the existing project.
- Reverse proxy: Nginx.
- Deployment: Docker Compose.
- Communication between the Raspberry Pis: Wi-Fi + MQTT over TLS.
- Firmware: existing ESP32 Arduino/C++ firmware.

Do not introduce MongoDB or another unnecessary database. The central data platform must remain PostgreSQL with TimescaleDB.

SQLite is used exclusively as the gateway's persistent forwarding queue, not as a replacement for PostgreSQL.

## 6.1 Delivery guarantees

MQTT QoS 1 provides at-least-once delivery.

A message may be transmitted more than once if the gateway crashes after the core broker acknowledges the publish but before SQLite deletes the record.

Therefore:

- Every telemetry message must have a stable `message_id`.
- The ID must be preserved across retries.
- The core backend must perform idempotent inserts.
- Duplicate IDs must not create duplicate telemetry rows.
- The backend should log duplicate detection.

Do not claim exactly-once delivery.
